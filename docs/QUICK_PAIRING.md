# 短连接信息 · Mac 0.3.2 / Windows 0.4.2

## 用户操作

Windows 显示地址与短连接口令，点击「复制连接信息」复制一行文字
在 Mac 复制这行文字后，点击「粘贴连接信息」，再点击「连接」
也可以分别填写地址与口令
正常流程不再展示几千字符的旧配对码，也不要求保存配对文件

Mac 已补齐标准编辑菜单，支持 Command+V、全选等系统快捷键
粘贴按钮直接读取剪贴板，自动填入两项，省去额外的预览步骤
旧格式移入「旧版配对码或文件」，仍然兼容，保留原有身份与证书校验

## 协议边界

短口令为 20 个 Base32 字符，100 bit；显示时分为五组
由一次性随机 bootstrap 的 SHA-256 派生，口令不通过网络发送
禁止直接改成六位数字：当前握手的密文允许离线校验口令，短数字需要另行设计 PAKE 等协议

Windows 在同一 HTTPS 端口提供 `/v1/pairing/quick`，只返回 AES-256-GCM 密文
密文封装原有邀请资料，nonce 12 字节、tag 16 字节
AAD 为 `CopyBridge quick pairing v1`
密钥为 SHA-256(context + 换行 + 去掉分隔符的大写口令)

Mac 首次请求仅下载公开密文，不发送口令、bootstrap 或长期凭据
此请求不预先信任未知设备的 TLS 证书；真实性由本地口令解密认证决定
仅此引导请求接受未知证书，不复用正常 Network，也不携带 Authorization
禁止重定向、代理及非私有 IPv4 地址，响应限制 32 KiB，超时 10 秒

认证解密后，Mac 继续校验邀请有效期、设备字段、证书摘要、地址一致性
之后复用既有 CA、主机名和公钥固定的 TLS 连接进行正式配对
原有 `/v1/pair` 的尝试限制、长期凭据存储和同步接口鉴权不变
配对成功后立即清除短口令和引导密文；过期或已使用时返回 409

## 验证记录

- Windows 自检：口令格式、加解密、错误口令拒绝、篡改拒绝通过
- .NET 生成的测试密文在 Swift 解密通过，地址不一致和错误口令拒绝通过
- Mac 命名剪贴板测试：短信息填充、错误输入清除旧口令、完整旧配对码读取通过
- Mac 16,012 字符输入不截断，标准粘贴菜单存在
- 实际 Mac 窗口 Command+V 粘贴短口令成功；错误口令显示明确错误
- 实际「粘贴连接信息」按钮自动填好两项，点击连接完成两台真实设备配对
- 配对后 Mac 日志记录 PAIRED、CONNECTED、文字发布，Windows 显示可粘贴
- 配对后匿名短码引导返回 409，匿名设置接口返回 401

本轮没有重做设备自动发现，没有六位数字配对，也未做整机重启或大文件回归
